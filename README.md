# OsmToShapefile

MVP-модуль: загружает слои (дороги, здания, вода, лес) из OpenStreetMap через
Overpass API для заданного bbox и сохраняет каждый слой в отдельный shapefile.

## Запуск

```bash
cd OsmToShapefile
dotnet restore
dotnet run
```

Результат появится в `./output/*.shp` (плюс `.shx`/`.dbf` рядом — открывается
в QGIS/ArcGIS как обычно).

Bbox региона задаётся в `Program.cs` — на старте вписан пример (центр Москвы).
Свои координаты можно взять через bbox-finder.com или geocoding через Nominatim.

## Офлайн-тестирование (рекомендуется для разработки)

Публичный Overpass сейчас нестабилен (см. ниже), поэтому для итерации по коду
не обязательно каждый раз дёргать живой сервер. Положи файл
`sample-data/<layer>.json` (например `sample-data/roads.json`) — модуль
автоматически возьмёт данные из него вместо сети. Подробности и готовые
запросы для overpass-turbo.eu — в `sample-data/README.md`.

## Про нестабильность Overpass (важно!)

С апреля 2026 публичный `overpass-api.de` резко ужесточил анти-бот фильтрацию
из-за перегрузки (см. [обсуждение на community.openstreetmap.org](https://community.openstreetmap.org/t/overpass-api-error-406/143198)).
Ключевая находка (подтверждена вручную через `Invoke-WebRequest`): сервер
принимает запрос, только если он выглядит как реальная браузерная форма —
`application/x-www-form-urlencoded` с полем `data`, а не сырой текст запроса
как `text/plain`, плюс полный набор заголовков (`Origin`, `Referer` на
`query_form.html`, `Sec-Fetch-*`, `sec-ch-ua`). Именно так теперь и работает
`OverpassClient` — это уже не гипотеза, а рабочий вариант.

Что дополнительно сделано на случай сбоев:
- клиент шлёт `User-Agent` браузера + полный набор Sec-Fetch/sec-ch-ua заголовков;
- при ошибке с одним зеркалом клиент автоматически пробует следующее
  (`overpass-api.de` → `overpass.kumi.systems` → `maps.mail.ru`);
- если сервер отвечает `200 OK`, но с пустым результатом из-за таймаута/лимита
  (Overpass в этом случае кладёт причину в поле `remark`, а не в код ответа),
  клиент это ловит и тоже переключается на следующее зеркало.

Даже с правильными заголовками сама инфраструктура OSM сейчас периодически
перегружена (таймауты/OOM на конкретных запросах) — это уже вопрос текущей
нагрузки на бесплатный сервис, а не заголовков.

Если все зеркала всё равно недоступны — это, скорее всего, временная перегрузка
инфраструктуры OSM, а не проблема на твоей стороне. Стоит попробовать позже,
взять bbox поменьше (нагрузка на запрос ниже — меньше шанс упереться в таймаут),
либо поднять свой локальный Overpass-инстанс (готовые Docker-образы, например
`wiktorn/overpass-api`) — надёжнее для регулярной разработки, чем зависеть от
чужого перегруженного публичного сервера.

## Важно перед первым запуском

- Используется пакет `NetTopologySuite.IO.ShapeFile` (2.1.0), запись — через
  класс `ShapefileDataWriter`. Полей у всех фич одного слоя должно быть
  одинаковое количество и одинаковые имена — это уже учтено в
  `GeometryBuilder` (osm_id/name/layer).
- Overpass — публичный сервис с лимитами. При работе с большими bbox или
  частых запросах может резать (429/504) — тогда либо увеличивать паузы между
  запросами, либо смотреть зеркала (`overpass.kumi.systems`).
- Сейчас обрабатываются только `way` (линии/полигоны). Мультиполигоны через
  `relation` (например, сложные контуры леса/водоёмов) не разворачиваются —
  это следующий шаг, если понадобится точность.

## Как думаю развивать дальше (не реализовано)

1. **Проверка полноты OSM для региона.** Перед скачиванием — прикидка "а есть
   ли вообще там данные": считаем плотность объектов на км² по каждому слою
   и сравниваем с порогом. Если ниже порога — считаем регион непокрытым.
2. **Дешифровка по снимку** для слоёв, где OSM пуст/недостаточен:
   - вода/лес — через индексы NDVI/NDWI по Sentinel-2 (нужны мультиспектральные
     каналы, порядок величины работы — дни, не недели);
   - здания/дороги — через готовую предобученную ONNX-модель сегментации
     (сложнее, недели работы).
3. Слить результат дешифровки в тот же формат `Feature`/shapefile, что и
   OSM-слои — тогда весь остальной пайплайн (запись, сравнение) не меняется.

## Структура

```
OsmToShapefile/
├── Program.cs                 — точка входа, список слоёв и bbox
├── Overpass/
│   ├── OverpassClient.cs       — сборка Overpass QL запроса и HTTP-вызов
│   └── OverpassModels.cs       — модели JSON-ответа
└── Geo/
    ├── GeometryBuilder.cs      — Overpass-элементы -> геометрии NTS
    └── ShapefileWriter.cs      — запись слоя в .shp
```
